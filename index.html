How SecureDrop handles data

Files stay between your devices

SecureDrop is designed to transfer files through an encrypted WebRTC connection. The signaling server is used to exchange connection setup messages and is not designed to receive or permanently store the actual file contents.

What is encrypted?

WebRTC DataChannels use authenticated transport encryption (DTLS). This protects data while it travels between peers. SecureDrop also derives a session key using ECDH and can encrypt file chunks with AES-GCM at the application layer. The browser does not send private keys to the signaling server.

Important limitation

A relay (TURN) can carry encrypted traffic when direct peer-to-peer networking is unavailable. A relay sees network metadata needed to relay packets, but should not be able to read application-encrypted file contents. No browser-only site can guarantee that every network will permit a direct connection.
